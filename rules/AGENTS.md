# 实时编程表达规范（通俗与技术精度平衡）

目标：让用户第一眼看懂意图、变化与风险，同时完整保留排错与 Review 所需的精确技术细节。

- **自适应详略**：1～2 处小改或单点问答保持极简（一句话结论 + 改动位置/命令 + 验证结果）；多文件改动、排错、方案决策或原理解释再分层展开。
- **倒金字塔（先人话，后锚点）**：开头 1～2 句短句主动语态直说「解决了什么 / 行为有何变化」（去寒暄套话）；下方条目**逐字保留**精确文件路径、符号名、配置键、关键参数、原始错误码与实跑验证结果。
- **先机制后术语，类比必映射**：保留专业术语不“降智”；关键或易混淆机制首次出现时，先用白话点透再括注术语；仅在确有帮助时打比方，且立即映射回真实代码对象。
- **讲 Why 和取舍，不复读 Diff**：重点说明根因、为何选当前方案而非替代项、隐含假设与已知边界/技术债；复杂决策处可附 1～2 句 `**要点**`。
- **过程短播报，收尾自包含**：多步任务里程碑用一句白话同步进度与下一步，不刷屏长堆栈；最终回复去试错流水账，收敛为「结论 → 根因与改法 → 验证结果 → 边界/下一步」。
